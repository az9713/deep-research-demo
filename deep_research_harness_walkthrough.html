deep-research-harness.js — Line-by-Line Walkthrough

The ~350-line JavaScript engine behind Claude Code's /deep-research dynamic workflow. This page contains a full, copyable copy of the script and an annotation beside nearly every line — to demystify how a single registered script orchestrates ~100 subagents to produce a fact-checked, cited report.

The one-sentence model: the .js file is the engine (a fixed 5-phase pipeline); your question is the fuel, injected at runtime as args. Same engine + different fuel = the two runs in this project, whose script files were byte-identical because the task text was never in the code.

1. How Claude Code invokes this (dynamic workflow)

A dynamic workflow is a JavaScript program that orchestrates subagents deterministically — real loops, conditionals, and fan-out decide which agents run and how outputs combine. Claude Code runs the script in a sandbox and exposes a few primitives to it:

PrimitiveRole in this script
agent(prompt, opts)Spawn one subagent; with opts.schema it returns a validated object
pipeline(items, ...stages)Run each item through stages with no barrier (search → fetch flow independently)
parallel(thunks)Run concurrently and wait for all (used for the 3-vote verify)
phase(title)Open a progress group in the /workflows UI
log(msg)Emit a progress line
argsYour question, injected verbatim from Workflow({args})

The script registers itself via meta.name = 'deep-research' (lines 1–6). You invoke it with one tool call — Workflow({ name: "deep-research", args: "<your question>" }) — and Claude Code looks up the registered script, persists a per-run copy to disk (deep-research-<runId>.js), runs the body with args injected, streams phase()/log() output to the UI, and returns the script's final return value.

2. How args flows in and through

Injection & capture

You never see args declared — Claude Code injects it. Line 92 type-checks and trims it into QUESTION; lines 93–95 fail fast if it is empty. This is exactly how the thesis / valuation briefs entered each run.

Threading into every phase

QUESTION is embedded in the Scope (l.96–105), Search (l.130), Fetch (l.139), Verify (l.154), and Synthesis (l.306) prompts — one argument fans out to ~100 agents, each anchored to your question. Change args and the whole run re-aims.
